# 平板浏览器（Flutter + Android WebView）

一个面向 **Android 平板** 的受控浏览器：能正常浏览在线网页与本地静态/动态网页，同时用
**白名单 / 黑名单** 限制可以访问的网址。名单支持具体网址、带通配符的 pattern、以及域名或 URL 前缀；
黑白名单可以同时生效，并按照「更具体者胜」的规则解决重叠。

## 版本与发布约定（每次出版本都要遵守）

1. **版本号只增不减**。默认把 `pubspec.yaml` 的 patch 位 +1，构建号（`+N`）同时 +1；
   小版本用 `--bump minor`，大版本用 `--bump major`。脚本会拒绝比当前版本更低的版本号。
2. **发布压缩包的文件名必须带版本号 + 日期时间**，用来区分不同批次：
   `xEduBrowser-v<版本>-<YYYYMMDD-HHMM>.zip`，例如 `xEduBrowser-v1.0.1-20260922-0310.zip`。
3. 包内附 `SHA256SUMS.txt`，包外同名 `.sha256`，上传后与服务器端 sha256 比对一致才算发布成功。
4. 打 tag `v<版本>` 并推送；`dist/` 不入库（`.gitignore` 已忽略）。

发布一条命令搞定（见 `tool/release.sh`、`tool/upload_dist.sh`）：

```bash
tool/release.sh --upload --push        # patch +1 → 构建 → 打包 → 提交/打tag/推送 → 免密上传
tool/release.sh --bump minor           # 只构建打包，不上传
```

## 一、功能概览

**浏览能力**

- 在线网页：`http` / `https`，开启 JavaScript、DOM Storage、Cookie，支持现代 SPA。
- 本地静态网页：`file:///...` 直接打开本地 HTML/CSS/JS/图片。
- 本地动态网页：内置 `http://127.0.0.1:<端口>` 本地服务器，让 `fetch` / `XMLHttpRequest` / ES module /
  Web Worker 等依赖正常 http 源的功能可用（`file://` 源下这些会被浏览器同源策略限制）。
- 多标签页、前进/后退/刷新/停止、进度条、页面标题。
- **全屏浏览界面**：没有地址栏，唯一的顶栏只有导航按钮、标签页和右上角的菜单；
  网页正文占满其余空间，孩子无法在浏览器里输入网址。
- **首页只有书签方块**：按分类分组，没有「添加/删除书签」按钮。
- **书签在设置里管理**：右上角菜单 →「设置」→「书签」，可添加书签、从本地目录导入、管理分类、
  修改标题或删除；添加书签时会**同时把该网址和它所在的网站（本地网页是所在目录）加入白名单**。
- 家长验证（见下）。

**过滤能力**

- 白名单 + 黑名单可同时配置，条目支持通配符 `*`、`?` 与前缀匹配。
- **包含关系自动判定**：白名单条目与黑名单条目若存在子集关系，由**更具体（子集）**的一方决定动作，
  与它在哪个名单无关。
- **互不包含时**按可配置的冲突解决方式处理，**缺省黑名单优先**。
- 拦截粒度覆盖 **主页面导航**、**重定向**、**子资源请求（图片/脚本/XHR/fetch）**、**弹窗**；
  本地服务器返回的页面同样受策略约束。
- 策略测试器：输入任意网址，显示命中的白/黑名单、两两包含关系、最终判定与原因。
- 访问日志：记录每一次放行/拦截及其原因。
- 规则导入/导出（JSON）。

## 二、过滤语义（核心规范）

### 2.1 名单条目的写法

一条名单条目就是一段**模式文本**，例如：

| 写法 | 含义 |
|---|---|
| `https://school.test/lessons` | 该 URL 前缀下的一切 |
| `school.test` | 任意 scheme 下的 `school.test` 前缀（自动补 `*://`） |
| `https://*.example.com/*` | `example.com` 的任意子域，任意路径 |
| `*://*/ads/*` | 任意站点下路径中含 `/ads/` 前缀的地址 |
| `file:///sdcard/pages/`、`/sdcard/pages/` | 本地文件目录 |

**自动补 scheme**：条目若不含 `://` 且不以 `*:` 开头，会自动补上 `*://`，因此 `school.test`
同时匹配 `http://school.test/...` 与 `https://school.test/...`。本地路径写法（以 `/` 开头）同样适用，
`/sdcard/pages/` 会变成 `*:///sdcard/pages/`，能匹配 `file:///sdcard/pages/...`。

### 2.2 匹配规则：前缀匹配

> 匹配时，以名单为前缀的网址都被认为成功匹配该名单。

实现方式：每条条目在编译时**隐式追加一个 `*`**，然后对整条 URL 做整体匹配。所以：

- `https://example.com/news` 匹配 `https://example.com/news`、`https://example.com/news/2026`；
- `school.test` 匹配 `https://school.test/lessons/1`；
- 前缀匹配**不是子串匹配**：`school.test` 不匹配 `https://sub.school.test/x`，`ads.example.com`
  也不匹配 `https://cdn.example.com/x`。

通配符：`*` 匹配任意长度（含空）字符串，`?` 匹配恰好一个字符，`\*` 表示字面量 `*`。

### 2.3 归一化

匹配前对 URL 做统一处理，避免用大小写或默认端口绕过名单：

- scheme 与 authority（域名、端口）**转小写**；路径、查询串**保持大小写敏感**；
- 去掉默认端口（`http:80`、`https:443`）；
- 去掉 fragment（`#...`）；
- 没有 scheme 的输入按 `https://` 处理。

### 2.4 冲突解决：更具体者胜

当某网址**同时命中白名单和黑名单**时，按下面的顺序判定：

1. 把命中的条目按「语言包含关系」做偏序，取**极小元**（即最具体、没有任何其他命中条目是它真子集的那些条目）；
2. 若极小元**全部来自同一个名单** → 由该名单决定（放行 / 拦截），与包含关系方向无关；
3. 若极小元**来自两个名单**（即出现**等价**条目或**互不包含**的条目）→ 由**冲突解决方式**决定，
   缺省 **黑名单优先**。

包含关系是**精确判定**的，不是字符串前缀的近似：条目先编译成 NFA，然后把「超集」一侧做子集构造
（on-the-fly determinization）得到 DFA，再在乘积自动机上搜索「子集侧接受、超集侧不接受」的可达状态。
只要找不到这样的状态，就证明 `L(子集) ⊆ L(超集)`。字母表只取两侧出现过的字面字符加一个「其他」等价类，
因此搜索空间有限且很小。

**判定示例**（`W` = 白名单，`B` = 黑名单，网址 = `https://a.test/x/y/z`）：

| 命中情况 | 关系 | 结果 |
|---|---|---|
| `W: https://a.test/x/y`，`B: https://a.test/x` | W ⊂ B | **放行**（白名单更具体） |
| `W: https://a.test`，`B: https://a.test/x` | B ⊂ W | **拦截**（黑名单更具体） |
| `W: https://a.test/x`，`B: https://a.test/x` | 等价 | 按冲突设置，缺省**拦截** |
| `W: *://*.a.test`，`B: *://a.test` | 互不包含 | 按冲突设置，缺省**拦截** |
| `W: https://a.test`、`W: https://a.test/x/y`、`B: https://a.test/x` | 极小元是 `W: …/x/y` | **放行** |

上表最后一行说明了多条目时的推广：只要「最具体的那一条」全部属于同一名单，就按该名单处理。
冲突解决方式可切换为**白名单优先**，此时第 3、4 行改为放行。

### 2.5 未匹配任何名单

| 设置 | 行为 |
|---|---|
| **自动（缺省）** | 白名单非空 → 拒绝；白名单为空 → 放行。即「配了白名单就是白名单模式，只配黑名单就是黑名单模式」。 |
| 一律放行 / 一律拒绝 | 显式指定，不受白名单是否为空影响。 |

关闭的条目、空条目不参与匹配，也不会让「白名单非空」成立。

### 2.6 严格域名边界（可选，缺省关闭）

因为规范要求的是**前缀匹配**，`example.com` 这类只写到域名的条目会匹配
`https://example.com.evil.test/...`（它确实以 `https://example.com` 为前缀）。在敌对环境下这是可利用的。

打开「严格域名边界」后，这类条目会被展开成一组边界模式：域名本身（精确匹配）、`域名/`、`域名:`、
`域名\?`、`域名\#`。于是 `example.com` 只匹配 `example.com`、`example.com/...`、`example.com:8080/...`
等真正的同域地址，不再匹配 `example.com.evil.test`。含路径的条目不受影响。

> 注意 `?` 与 `#` 在模式里是元字符，展开时必须转义写成 `\?`、`\#`，否则 `host?` 会匹配 `host` 加任意一个字符，
> 等于把上面这个洞又打开。这一点有专门的向量用例守护。

## 三、本地网页：file:// 与内置本地服务器

两条路径都能用，且**都由同一套名单约束**：

1. **`file://`**：在「设置 → 书签 → 添加书签」里输入绝对路径（`/sdcard/pages/index.html`）或
   `file:///...`，或点对话框里的「浏览本地文件」翻到存储卡上的 HTML；顶栏菜单里的
   「打开本地网页」也可以临时打开一个文件。
2. **本地服务器**：把网页放进应用私有目录（或设置里指定的根目录），通过
   `http://127.0.0.1:8787/...` 访问。动态页面的 `fetch`/XHR/ES module 在这里工作正常，且完全离线。

关键设计：本地服务器的 URL 会先**映射回它所代表的 `file://` 地址**再交给策略判定，
所以一条 `file:///sdcard/pages/` 规则同时管住 `file://` 直接打开与本地服务器两种访问方式；
书签与白名单条目也因此一律存成 `file://` 形式，并且本地路径会做百分号编码，
与 WebView 实际加载、回报的地址逐字符一致。
命中黑名单的本地请求返回 HTTP 403 与拦截页面。

服务器行为：只监听 `127.0.0.1`，只允许 GET/HEAD，目录无 `index.html` 时给出目录列表，
按扩展名返回正确 MIME（含 `text/javascript`、`application/wasm`），并拒绝任何越出根目录的路径穿越。

> Android 11+ 访问 `/sdcard` 需要「所有文件访问权限」。应用私有目录不需要任何权限，
> 所以最省事的做法是把本地网页放进应用目录再通过本地服务器打开。

**书签**

- 首页**只有书签方块**：按分类分段，每段是分类名 + 数量 + 该分类的方块墙；首页上没有任何
  添加/删除控件。
- 磁贴是**方块缩略图 + 下方标题 + 下方域名/文件夹**；缩略图是页面截图，失败时退化为按域名生成的字母方块。
- **分类内可拖动排序**：长按方块拖到另一个方块上，即占据它的位置（跨分类拖动＝移动到该分类）。顺序会持久化。
- **书签的增删改都在「设置 → 书签」里**（右上角菜单 →「设置」）：添加书签、从本地目录批量导入、
  分类管理、在列表里改标题 / 改分类与白名单 / 删除。
- **添加书签时同时放行两件事**：该网址本身，以及**包含该网址的网站**；本地网页则是**它所在的目录**
  （文件直接放在存储卡根目录时只放行该文件，避免一条规则放行整张存储卡）。
- **从本地目录批量导入**：选一个目录，遍历该目录及其**一级子目录**，把里面的 HTML 页面作为书签加进指定分类。
  标题自动取页面 `<title>`（没有则用文件名），导入前有预览，重复导入会跳过已存在的（上限 200 个/次）。
- 分类可新建/重命名/删除；删除分类**不会删书签**，它们会回到「未分类」。
- 可从被拦截页面「加为书签并允许访问」：同样按「网址 + 所在站点」放行后重试打开。
- 删除书签时可以选择同时移除它带来的白名单条目（若该条目仍被其他书签使用则保留）。
- 对话框里的「**浏览本地文件**」可以直接翻到 `/sdcard` 里的 HTML，选中后地址自动填入。
- 本地网页（`file://`）的放行范围**包含它所在的整个目录**（规则形如
  `file:///sdcard/Books/Caterpillar/`）：翻页书这类本地 HTML 会引用同目录下的 `mobile/`、
  `files/` 等成百上千个相对资源，只放行那个 `.html` 会让页面变成**空白页**。

> **本地地址一律写成规范形式。** 存储卡上带空格或中文的文件名会被**百分号编码**
> （`/sdcard/课件/第 1 课.html` → `/sdcard/%E8%AF%BE%E4%BB%B6/%E7%AC%AC%201%20%E8%AF%BE.html`），
> 因为 WebView 回报的就是编码后的地址，而过滤是按字符串前缀比较的——规则和地址必须逐字符一致。
> 同理，内置本地服务器提供的页面**在名单判定中一律按它代表的 `file://` 地址**处理，
> 因此书签与白名单条目也存成 `file://` 形式。旧版本把这类书签存成
> `http://127.0.0.1:<端口>/...`，规则永远匹配不上、点开就提示无法访问；启动时会自动改写成
> `file://` 形式修复。

> **交互说明**：长按方块＝拖动排序；方块上不再有 ⋮ 菜单，改标题/换分类/删除都在设置里。

> **导入的白名单范围**有三档：**整个导入目录**（缺省，一条规则覆盖所有导入页面**及其同级资源**）、
> 每个文件各自一条规则、不加入白名单。选「整个导入目录」时规则形如 `file:///sdcard/course/`，
> 本地课程页面通常还能引用同目录的图片/JS，这一档才真正可用。

> **白名单范围提醒**：添加书签默认放行**该网址前缀 + 它所在网站**，所以站内其他路径也可访问；
> 页面里来自其他域名的子资源（CDN 的 JS/CSS/字体、第三方统计）仍会被子资源拦截挡下，
> 页面可能显示不全——这是按域名过滤的固有代价，需要时把用到的 CDN 域名也加进白名单。

**家长验证**

- 打开「设置」**和「黑白名单管理」**都会先要求家长验证；验证是**包裹式**的：
  任何入口都绕不过去，未通过时被保护界面**根本不会被构建**（连顶栏的导入/导出按钮也不会出现）。
- 缺省验证方式是**家长密码**：首次进入时要求设置（输入两次），之后每次都要输入它。
  密码只以 **盐 + 迭代 SHA-256 哈希**保存在应用私有配置里，既不落明文，也不会下发给原生层。
- 连续输错 5 次锁定 30 秒，锁定期内输入框禁用；正确输入一次即清零重试计数。
- 也可以把验证方式切换成**算术题**（一位数乘法／加法／混合，1–5 题连续答对），适合不想记密码的场景。
- **密码无法找回**：忘记后只能清除应用数据（规则、书签、设置都会一起清空）。设置页里有中文提示。

```
├── policy/Glob.kt              Dart 引擎的 Kotlin 移植（匹配 + 包含判定）
├── policy/PolicyEngine.kt      Dart 判定流程的 Kotlin 移植
├── PolicyWebView.kt            WebView + 四个拦截点
├── PolicyWebViewFactory.kt     PlatformView 工厂
├── PolicyBridge.kt             通道注册与 view 注册表、主线程派发
├── ThumbnailCapture.kt         WebView 截图 → PNG（书签缩略图），尺寸计算为纯 JVM 可单测
└── MainActivity.kt             Flutter 引擎装配
```

**为什么过滤逻辑要写两遍？** 主页面导航可以异步判定（Dart 说了算），但
`WebViewClient.shouldInterceptRequest` 在后台线程同步返回，无法等待 Dart 的异步通道调用。
因此 Kotlin 侧必须持有一份可以同步判定的引擎副本，Dart 侧通过 `setPolicy` 把配置推给它。
两份实现共用同一份测试向量（见下节），保证语义一致，而不是各写各的。

原生层的线程模型、四个拦截点、设置映射、拦截页渲染与 Gradle 配置细节，见
`docs/ANDROID_NATIVE.md`；通道契约见 `docs/CONTRACT.md`。

## 七、已知限制

1. **未在真机/模拟器上运行过。** 本环境没有连接任何 Android 设备，也没有系统镜像，
   因此验证到的是：`flutter build apk --release` 成功产出 APK、Dart 侧 304 个测试通过
   （含各管理界面的真实渲染测试）、Kotlin 侧 627 个测试通过。真机上的 WebView 渲染、
   手势、以及第 2 条描述的标签页显示问题，仍需要在设备上确认。
2. **多标签页用 `IndexedStack` 保活**。这样切标签不会重新加载页面，但 Android 混合渲染下
   隐藏的 platform view 理论上存在仍然可见的风险；若真机上出现该问题，改成只挂载当前标签页并
   用原生侧保活即可（`PolicyBridge` 已按 viewId 独立管理 WebView 生命周期）。
3. **下载行为**：下载请求也要过名单。允许的下载交给系统下载器，保存到应用私有外部目录
   （`Android/data/<包名>/files/Download`），并带上当前页面的 Cookie；被拒绝的下载不会启动，
   只记录一条拦截日志。若需要别的保存位置或用户可见的下载目录，需在原生侧改 `DownloadListener`。
4. **`file://` 跨域放宽**：为让本地动态页面可用，缺省开启了
   `allowUniversalAccessFromFileURLs`。这会放宽本地页面的同源限制；更安全的做法是关掉它，
   统一走本地服务器（推荐用法）。
5. **WebView 行为随系统版本变化**：不同 Android 版本的 WebView 内核版本差异较大，
   极端复杂的站点可能需要针对内核版本回归测试。
6. **书签缩略图截图未在真机验证过，且现在的书签基本不会有截图**：`captureThumbnail` 的 Kotlin
   代码已编译并通过 15 个纯 JVM 尺寸/空白判定单测，但 `WebView.draw` 的实际成像效果没有设备可
   验证（无真机、无模拟器、容器内无 `/dev/kvm`）。另外，书签现在只能在**设置页**添加（首页没有
   添加按钮、浏览器也没有地址栏），那里没有正在显示的页面可截图，所以磁贴一律使用按域名生成的
   字母方块；被拦截页面的「加为书签并允许访问」同样不截图。原生截图能力及 `setBookmarkThumbnail`
   仍在，日后若加回「收藏当前页面」入口即可继续使用。
7. **导入的 HTML 标题按 UTF-8 解码**：页面若用 GBK 等其它编码声明 `<title>`，标题可能显示为乱码
   （书签本身仍正常，改标题即可）。需要的话可以按 `<meta charset>` 做编码嗅探。
8. **导入只认一级子目录**：这是需求规定的规则，因此所选目录**直接放置**的 HTML 不会被导入；
   对话框会明确提示这一点，避免用户以为扫描失败。
9. **家长密码没有找回通道**：这是刻意的——任何找回后门都等于验证失效。忘记密码只能清除应用数据，
   或用 `adb` 直接改 `settings.json`（删掉 `parentalPasswordHash`/`parentalPasswordSalt` 两个键，
   下次进入会重新要求设置）。
10. **包含判定的预算上限**：乘积自动机搜索上限 200000 个状态，超限时按「互不包含」处理并走冲突解决方式，
   不会卡死界面；人工撰写的规则远达不到这个规模。
